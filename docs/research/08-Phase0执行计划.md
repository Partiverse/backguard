# 08 · Phase 0 执行计划：语义层验证期（14 周，2026-10 → 2027-01）

> 本文把 [07 章 §5](07-产品定位与竞争优势.md) 的 Phase 0 展开为可执行计划。
> 定位：**Phase 0 是验证期，不是产品期**——目标是用最小工程量回答一个假设：
> **「看得懂的备份」是不是用户真需求**（06 章语义层）+ 次要假设：「覆盖契约透明化」能否建立信任（02 章 §八）。
> 前置成果：[../prototype/](../prototype/) 已验证 L1/L2 渲染可行（20 个测试用例）。
> 关联：[06 语义化设计](06-语义化备份设计.md)（做什么）、[03 加密](03-加密方案.md)（manifest.json.enc 方案）、[05 云端](05-云端多端与传输.md)（B2 成本）。

## 0. 范围与不变量

- **做**：语义层（L0/L1/L2 + 恢复 README + 演练）、覆盖审计 MVP、10–15 人外部验证、go/no-go 报告。
- **不做**（留 Phase 1+）：自研引擎、GUI/时间轴 UI、官方云、Shamir/PQ、移动端。
- 不变量（07 §4 风险的对策）：
  1. **引擎不换**：继续 borg/restic，语义层只做「引擎旁路」，不动仓库格式；
  2. **云端只增不减**：timeline 层是新增目录，随时可回退；
  3. **明文红线**：MANIFEST/STORY 永不出现完整文件名；凭据目录只写数量（prototype 已用测试锁定）；
  4. **先对自己诚实**：覆盖审计报告必须如实报告 backguard 自身的漏备（07 §4.4 反面教训）。

人员假设：1 名全职开发 + 1 名兼职（设计/用户研究/Windows 侧补位）。全部任务按此估时；单人执行则顺延至 18–20 周。

- [x] T0.2 v0 `backup.sh` / `backup.ps1` 接入：新增 `semantic/semantic.sh`（borg）与 `semantic/semantic.ps1`（restic），备份成功后导出清单 → convert → generate → timeline 随内容池上传；调用点全部非致命（语义层失败只告警）。（2026-09-29）
- [x] T0.3 run JSON 落盘保留：`$LOG_DIR/runs/`（borg）/ `%LOCALAPPDATA%\PartiverseBackup\runs`（restic），滚动保留 60 份。（2026-09-29）
- [x] T0.4 GitHub Actions：新增 `semantic` 三平台矩阵 job（unittest + demo E2E + zipapp 构建）；linux/macos/windows 备份 job 增加语义时间轴产物断言。（2026-09-29）
- [x] T0.5 真实引擎端到端：本机 borg 1.4.5 / restic 0.19.1 合成两代仓库全链路验证。**真实数据抓出 4 个 fixture 测不到的 bug 并全部修复**：①borg 1.4 mtime 是 ISO 字符串而非 epoch；②restic ≥0.19 `ls --json` 的 `name` 是 basename，目录结构必须取 `path`；③单文件被两级细化误写成目录名（隐私红线级 bug，引入 known_dirs 目录证据机制）；④macOS `/usr/bin/bg` 与 CLI 撞名（接入层）。测试 25 项全绿。（2026-09-29）

**退出**：三平台 CI 绿；真实仓库产物经得起作者自己「裸文件管理器只读」检查。

### M1（W3–W6）语义层 v0.1：全自动 + dogfood

- [x] T1.1 `manifest.json.enc` 落地：age 双 X25519 recipient（主身份 + 恢复码包裹的救援身份；age 规范要求 passphrase stanza 独占，故不用 scrypt 直包清单）。`init-keys.exp`（expect 驱动 age -p 的 /dev/tty，恢复码单一事实源 + 包裹后闭环验证）；`bg manifest` 子命令产出全量清单（完整文件名只进密文账本）；`seal_manifest` 集成进 semantic.sh/ps1；restore.md 双路径恢复指引。真实 E2E：密封 → 主身份解封 → 恢复码救援解封 全通。（2026-09-29）
  - 教训：`printf | age -p` 管道喂不进（age 只读 /dev/tty），bash 首版显示码 ≠ 包裹码；pty/expect 驱动为正解。
- [ ] T1.2 语义标签自动生成：无用户输入时按时段+日历启发（`morning/afternoon/evening/night` + 节假日/周末 `weekend`；检测到日历事件可后续增强，不做依赖）。（1d）——时段启发已随 M0 落地（semantic.sh/ps1），日历增强待做
- [ ] T1.3 聚类参数调优：用作者真实 30 天数据回放，校准 Top-K/权重/两级目录命名（06 §8.2 的退化行为测试：百万小文件、单一大文件）。（2d）
- [x] T1.4 「备份在活着」通知：ntfy 落地（semantic.sh `notify_story` + semantic.ps1 对称）：STORY 标题 + Top-2 变更 bullet 推送到 `SEM_NTFY_URL`；可选 sidecar（未配置即静默跳过）、非致命；mock server E2E 验收 POST 内容。（2026-09-29）
- [x] T1.5 连续备份天数与断档提醒：断档 >48h 时 STORY 置顶「⚠️ 距上次备份已约 N 天」；无变化快照在断档场景下的措辞从「一切正常」改为「备份已恢复运行」；顺带修复时间口径——borg 的 start 是 naive UTC，编排层补时区转本地，bg 侧 `local_naive` 统一显示（E2E 实测抓到）。（2026-09-29）
- [ ] T1.6 dogfood 期：团队全部设备（≥3 台：macOS/Linux/Windows 各一）daily 运行 2 周；每周回收一次「看 STORY 的体感」记录。（持续 2 周，0.5d/周）

**退出**：无人值守运行 ≥2 周无人工干预；manifest.json.enc 可被 age 命令行独立解开（逃生恢复的前置验证）。

### M2（W5–W8，与 M1 后半并行）覆盖审计 MVP

- [ ] T2.1 显式排除清单导出：聚合 v0 现有 platform 配置的排除规则 + 引擎内建排除，产出机器可读 `exclusions.json` + 人类可读段落（进 MANIFEST 附页）。（2d）
- [x] T2.2 预检器 `bg preflight`：备份前检查并拦下已知坑（02 §八.1 / 07 §4.6）。已落地（2026-09-29）：include 路径有效性（error）、iCloud `.icloud` / OneDrive recall 位占位文件浅扫（warning，浅层限深防扫描爆炸）、.git 静默排除检测（对位信任危机）、磁盘空间、引擎版本下限（borg≥1.2 / restic≥0.16，bash 侧）、凭据外部化静默失效（PASSCOMMAND 的 CLI 在位 + rbw-agent 解锁，bash 侧）。分级 exit code：error=2 中止备份 / warning=1 继续留日志；`SEM_PREFLIGHT=0` 可关。分层约束：bg 只做纯文件系统检查（Mimosa L3 拦 Python 侧子进程调用），引擎/凭据检查在编排层。注入 E2E：占位+.git → rc=1 两警告，缺失路径 → rc=2。
- [ ] T2.3 每快照覆盖报告（MANIFEST 附加段或独立 `COVERAGE.txt`）：本次**排除了什么、为什么、有多少字节**；连续 N 次未覆盖的大目录置顶告警。（3d）
- [ ] T2.4 排除规则变更检测：diff 上次 exclusions.json，变更主动写入 STORY（「这次起 X 不再被备份」）。（1d）
- [ ] T2.5 云同步占位文件专项：macOS `.icloud`/`*.icloud`、Windows OneDrive placeholder 的识别与「半真文件」计数（07 §4.6 事故高发区）。（2d）

**退出**：每次备份必然产出覆盖报告；作者自己被报告发现 ≥1 个真实漏备问题（自查不过 = 设计失败）。

### M3（W9–W10）逃生恢复与信任底座

- [ ] T3.1 仓库根 `README.md` 模板：目录含义、三档案解释（06 §2.2 的 WHAT-IS-THIS 文案并入）、manifest.json.enc 格式文档（schema 版本化）、逐平台恢复命令速查。（2d）
- [ ] T3.2 `rescue` 单脚本：bash + PowerShell 各一份，无 Python 依赖——指引 + 调用 age 解密清单 + 调用 borg/restic 逐文件提取；目标「新机器 30 分钟内取回任一文件」。（4d）
- [ ] T3.3 强制恢复码：初始化时生成 128-bit 恢复码并要求抄写确认（03 §2.3 Apple ADP 先例；作为 stanza 之一，密码丢失时可解）。（2d）
- [ ] T3.4 演练自动化：`bg drill` 抽样 5 个文件走 rescue 路径恢复并校验 hash，结果写 `timeline/.../rescue-test.txt`；每 30 天自动跑一次；可选 `--from-bitwarden` 路径——从密码管理器（rbw，05 §7）拉取恢复材料，真实走一遍「解救援身份 → 解 manifest.json.enc」，把「vault 里的恢复材料真的可用」从假设变成周期性验证的事实（前提红线：恢复码纸质抄写仍是第一恢复路径，vault 只算第 2 份副本，03 §2.3）。（2d）

**退出**：在一台擦干净的虚拟机上，只凭云端目录 + rescue 脚本 + 恢复码完成盲恢复；演练记录可见。

### M4（W11–W14）外部验证与决策门

- [ ] T4.1 招募 10–15 人（即刻社区 + 个人网络；配额：≥4 非技术背景、≥2 Linux 用户）。（2d）
- [ ] T4.2 引导安装：单脚本 init（沿用 v0 init.sh 思路）+ 20 分钟远程陪同首次备份；BYO B2/R2 桶或 NAS。（3d）
- [ ] T4.3 两周日记研究：不主动提醒，仅在第 7/14 天回收问卷——核心问题：「**你这周看过备份内容吗？能说出上次备份了什么吗？**」（部署 1d + 回收 0.5d/次）
- [ ] T4.4 半结构化访谈 30 分钟/人：STORY 是否被主动提及；隐私边界体感（目录名暴露是否舒适；strict 模式意愿）；覆盖报告是否改变行为。（5d）
- [ ] T4.5 汇总 go/no-go 报告：指标（§4）+ 访谈证据 + 下一阶段范围建议；公开发布调研复盘（延续 07 §4.4 的「对自己诚实」人设）。（2d）

## 4. 度量与决策门

定量指标（埋点只记事件计数，不传内容）：

| 指标 | 目标 | 反证 |
|---|---|---|
| STORY/时间轴打开率（用户侧自报+问卷） | ≥60% 用户每周至少看 1 次 | <30% 且无主动提及 → 假设存疑 |
| 备份连续性（部署用户中断 >72h 的人次） | 环比下降 | — |
| 覆盖报告发现的意外排除/占位文件 | 每用户 ≥1 个真实问题 | 0 发现 → 覆盖契约无感知价值 |
| 盲恢复演练成功率 | 100%（所有人） | <100% → M3 不合格，门禁卡住 |
| 安装到首次成功备份耗时 | P50 < 45 分钟 | — |

定性判据（访谈编码）：
- ≥7/10 用户在**未被提示**的情况下主动描述语义层价值（「像日记」「知道照片在里面」）；
- 目录名暴露的隐私体感：≤2 人明确不适且 strict 模式不能解决；
- 覆盖报告改变行为：≥4 人据报告调整过排除规则或接线盘。

**Go**：Go 判据全部满足 → Phase 1（GUI + BYO 矩阵 + 恢复体系产品化，07 §5）。
**Pivot**：语义层弱、覆盖审计强 → 转向「诚实备份审计工具」（对 Backblaze 信任危机的独立卖点）。
**No-go**：两个假设都弱 → 停止，保留 research/ 与 prototype/ 作沉淀。

## 5. 风险登记（Phase 0 特有）

| 风险 | 概率 | 缓解 |
|---|---|---|
| STORY 目录名暴露引发隐私不适 | 中 | strict 模式常备；访谈专项；默认两级目录名、凭据类永不出名（原型已实现） |
| borg/restic 清单字段差异/版本漂移 | 中 | run JSON 中间层隔离（原型已实现）；CI 锁定最低引擎版本 |
| 外部用户安装门槛（Python/命令行） | 高 | 单文件 zipapp + init 脚本 + 陪同安装；此门槛本身也是 Phase 1 GUI 必要性的证据 |
| 单人 bus factor | 中 | 全部产物在 GitHub；兼职覆盖关键路径；文档先行 |
| dogfood 样本过小导致误判 | 低 | 外部验证 10–15 人补足；指标预设阈值避免事后合理化 |
| 服务器成本 | 低 | BYO 桶，用户自付（B2 10GB 免费 / $6.95/TB，05 §1）；验证期无自有后端 |

## 6. Phase 0 预算

- 存储：全部 BYO，≈0（作者自用 <2TB，约 $14/月 B2）；
- 域名/CI/ntfy：≈$10/月；测试机折旧忽略；
- 现金支出合计 < $100/月——Phase 0 的成本几乎全是时间，这正是 07 §4.1「语义层在现引擎上即可实现」结论的价值。
