# 05 · 云端备份 / 多端备份 / 跨端备份与文件传输调研

> 调研时间：2026-09。本文为 backguard 云与多端架构选型提供依据。
> 关联：[03 加密方案](03-加密方案.md)（客户端加密）、[04 性能架构](04-性能架构.md)（分块与 manifest）、[07 产品定位](07-产品定位与竞争优势.md)。

## 0. TL;DR

- **个人备份性价比之王是 Backblaze B2（$6.95/TB/月，出口免费额度 3 倍存储量）**；**Cloudflare R2（$15.36/TB/月，出口永久 $0）是最佳「恢复副本」**。B2 主存 + R2 镜像是 2026 年社区主流的双云 3-2-1 玩法。AWS S3 对个人最差（存储 3 倍于 B2 + 恢复 $0.09/GB）。
- **MinIO 社区版 2025-12 进入维护模式、2026-04 归档**——自建 S3 应转向 Garage / SeaweedFS；且 minio-go SDK 为 AGPL，闭源商业产品不能静态链接。
- E2E 云对标：**Filen Pro III 2TiB €8.99/月**是当前性价比+架构（分块+每文件密钥+元数据加密）都最值得借鉴的对象；MEGA 的密码派生主密钥设计曾出密钥恢复攻击（eprint 2022/914），是反面教材。
- 多机隔离：restic 全有全无（需 `--private-repos`/分仓）、borg 官方明确不建议多客户端共仓（AES-CTR nonce 风险）、**Kopia repository server 的 per-user 模式是目前最好的隔离先例**（但有跨用户去重存在性泄漏）。
- 跨端元数据是差异化机会：restic 保留 macOS resource fork（经 xattr）但**无人支持 NTFS ADS**；Windows ACL 只有 Kopia/VSS 部分覆盖。backguard 应做「sidecar 元数据 + 跨端降级矩阵」。
- iOS 只能做「相册备份客户端」（约 30 秒后台执行 + 机会式 BGProcessingTask），Android 可做全功能（Syncthing-Fork 存活为证）。
- Tailscale 已是 2026 homelab 标配，「经 tailnet 备份回家 NAS」是成熟玩法，backguard 可原生兼容（无需自带 VPN）。

### 1.2 R2 + B2 组合的流行玩法（业界先例）

社区标准模式（2026 年仍在大量实践）：

1. **主仓库 → B2**（restic/kopia/Duplicacy 直接写 B2，存储最便宜，restic 的对象存储后端支持公认三者最佳）；
2. **镜像 → R2**：`restic copy` 到第二 repo，或 `rclone sync b2:bucket r2:bucket`；homelab 规模双云月成本个位数美元；
3. **恢复优先走 R2**（零出口）或 B2 免费额度内；再加 LAN/NAS 本地副本完成 3-2-1。
4. 变体：B2 + Cloudflare Bandwidth Alliance（经 Cloudflare 出口免 B2 流量费，官方确认 Fastly/Cloudflare/bunny 等合作方无限免费出口）——但 R2 出现后这个老玩法重要性下降。

### 1.3 文件协议：WebDAV / SFTP / SMB/NFS 与 rclone 抽象层

- **WebDAV**：坚果云是国内唯一主流 WebDAV 网盘，但**免费版每月仅 1GB 上传 / 3GB 下载**（官方博客确认不限速只限流量），只能做「配置/笔记级」备份目标；Nextcloud/群晖提供自家 WebDAV。WebDAV 普遍无原子 rename、无标准分块续传、list 性能差。
- **SFTP**：通用性最好（任何 VPS/NAS），但单连接吞吐受限、无对象语义；restic/kopia 都原生支持。
- **SMB/NFS**：局域网整目录镜像（NAS）合适，跨公网不可行（需 VPN，见 §4.3）。
- **rclone 作为统一抽象层**（[rclone.org/docs](https://rclone.org/docs/)，70+ 后端）：
  - **利**：一套代码覆盖长尾 provider；成熟的 crypt 后端（客户端加密包装器）、重试/VFS/serve 能力；MIT 许可对商业嵌入友好。
  - **弊**：① **依赖体积**——静态二进制数十 MB，作为 Go 库嵌入会把大量后端代码拖进 backguard，且其 library API 无稳定性承诺；② **性能损耗**——VFS/内存缓冲层，分块参数需调优，原生 SDK 通常更快；③ **密码安全**——config 中密码是 `obscured`（**可逆混淆，不是加密**），必须启用整配置文件加密（RCLONE_CONFIG_PASS）或由 backguard 用 OS 钥匙串代管；④ 每后端兼容性细节（如 R2 的 checksum 限制）仍需适配层兜底。
  - **建议**：backguard **原生实现核心后端（S3/B2/R2/Wasabi/OSS/COS + SFTP + WebDAV），rclone 仅作可选 sidecar 进程覆盖长尾**。

### 1.4 S3 兼容 API 的坑

- **强一致性**：AWS S3 自 2020-12 起全面强一致，但「兼容实现」≠一致：MinIO/Garage/R2 各有差异（Garage 明确不做线性一致）。备份索引依赖 list-after-write 可见性，**写入后立即 list 校验需保守处理**。
- **分段上传**：通用限制 5MB–5GB/段、最多 10,000 段、对象 ≤5TB → 大文件需自适应段大小。**未完成的 multipart 上传持续计费**，必须配置 abort-incomplete-multipart lifecycle。R2 特有坑：同段号重传失败会丢失原段、UploadPartCopy 不支持条件复制（[R2 S3 API caveats](https://developers.cloudflare.com/r2/api/s3/api/)）。
- **Checksum 算法**：R2 只允许 CRC-64/NVME 用 FULL_OBJECT、CRC32/SHA 系用 COMPOSITE，多数 API 不认 `x-amz-checksum-algorithm` 头——新版 AWS SDK 默认开启的 checksum 行为可能直接打挂 R2/B2，工具必须显式降级。
- **服务端加密/对象锁**：R2 不支持 SSE-S3/KMS（仅 SSE-C）、**不支持 Object Lock/WORM**、版本控制 API 未实现、对象标签未实现。→ 防勒索不可变备份只能落 S3（Object Lock）或 Wasabi（支持 Object Lock）；对 R2/B2 需用「版本化 + 删除审计 + append-only 网关」替代。
- **生命周期规则**：桶级 prefix 匹配误删风险；S3 的 IA/Glacier 层有 **128KB 最小计费对象**（去重型备份如果对象切得碎，冷层费用会爆炸）；R2 仅 STANDARD/STANDARD_IA 两层且只支持新版 lifecycle API。

- **路径一律小写**：S3 类大小写敏感、WebDAV 多不敏感，同一配置跨厂商行为不一致；小写是唯一安全交集（实测 123Pan 同名不同大小写会合并——大写路径会静默撞目录）。品牌原名（macOS/Windows/发行版）只作展示，落 `timeline/<设备>/profile.json`。

## 3. 多端与跨端

### 3.1 多机同仓：去重收益与隔离需求

- **去重收益**：restic/borg/kopia 均为内容寻址分块，同一 repo 内跨快照、跨主机去重；多台同 OS/同软件栈机器共享系统文件、应用二进制、容器镜像等相同块，社区实践普遍报告**额外两位数百分比**的节省。
- **隔离（设备互不信任）现状**：
  - **restic**：repo 权限全有全无——任何持有 repo 密码的客户端可读全部快照、可删数据。缓解：rest-server `--private-repos`（每客户端独立子 repo）+ `--append-only`（拒删改，防勒索但**无法经它 prune**，需另跑可信实例或 `restic copy` 到第二 repo）；O_EXCL 保证并行写互不干扰。
  - **borg**：官方 FAQ **明确不建议多客户端共仓**——安全模型上 AES-CTR 计数器可能跨客户端重用，另有排他锁竞争与 chunks cache 反复重建；推荐每客户端独立 repo（[borg FAQ](https://borgbackup.readthedocs.io/en/stable/faq.html)）。
  - **Kopia**：repository server 模式支持 **per-user 凭据 + 客户端加密（服务器只见密文 blob）**，是三者中隔离设计最好的先例；但已知泄漏面：**跨用户相同文件产生相同 content ID**，可被用来推断「某文件存在」（[kopia 论坛讨论](https://kopia.discourse.group/t/repository-server-multiple-users-and-dedup/639)、[issue #4772](https://github.com/kopia/kopia/issues/4772)）。
- **backguard 设计含义**：默认「一设备一命名空间」；账户级跨设备去重做成显式 opt-in，并在 UI 明示存在性泄漏权衡。

### 3.2 备份 vs 同步：Syncthing 模型

- **模型**：设备 ID（证书指纹）配对；**Global Discovery 服务器**（公网找对方）+ 本地广播发现 + UPnP/NAT 打洞，失败则回退**社区中继（relay，TLS 加密，中继看不到明文）**。
- **版本控制**：每文件夹可选 Trash Can / Simple / Staggered（类 Time Machine 时间梯度）/ External——说明「同步工具也被迫长出版本化历史」，佐证备份与同步边界模糊但保留策略仍是备份的核心。
- **边界**：同步=双向实时镜像、依赖两端在线、历史浅；备份=单向快照、离线可用、保留策略、不可变。Syncthing 是**设备间传输层**的优秀先例，不是备份替代品。
- **现状（2026）**：官方 Android 包装 2024 弃更，**Catfriend1 的 Syncthing-Fork 持续维护**（[GitHub](https://github.com/Catfriend1/syncthing-android)）；iOS 仍无官方客户端，第三方 **Möbius Sync（$14.99）** 存活、新的开源 **Synctrain** 崛起——iOS 后台限制是官方不出 iOS 版的根本原因。
- **LAN 直连加速**：Syncthing 本地发现自动走 LAN 全速；backguard 的「先局域网后云端」多源传输可直接借鉴（同一 manifest，块可来自任意 peer 或云）。

### 3.3 跨平台路径与元数据语义

| 问题 | 现状（业界处理） |
|---|---|
| **macOS resource fork / FinderInfo** | 现代 macOS 将其实现为 xattr（`com.apple.ResourceFork` / `com.apple.FinderInfo`）；**restic 备份 APFS 源时可经 xattr 完整保留并恢复回 Apple 文件系统**；坑：源在 SMB/FAT 上时元数据是 `._xxx` AppleDouble 伴随文件，restic 只当普通文件备份、恢复到 Mac 不会并回原生 xattr（[restic GitHub #1736](https://github.com/restic/restic/issues/1736)） |
| **NTFS ADS / Windows ACL** | **restic 与 Kopia 均不备份 NTFS 备用数据流（ADS）**；Kopia 不保留 Windows ACL/安全描述符与稀疏性，但支持 VSS 快照备份锁定文件；跨端恢复开源工具普遍是盲区 → **这是 backguard 的差异化机会** |
| **大小写语义** | NTFS/FAT 大小写不敏感、Linux 敏感：Linux 备份中仅大小写不同的两个文件恢复到 Windows 会冲突，需定义重命名/报告策略；Windows 保留名（CON/PRN）、非法字符（`: * ? " < > |`）、盘符语义（挂载点应为卷 GUID）需规范化层 |
| **POSIX 权限/xattr/ACL 跨端** | borg 支持 POSIX xattr/ACL（平台相关，btrfs NOCOW 等特有属性不保），但 borg 无原生 Windows；Kopia 把 ACL/xattr 存为元数据尽力恢复 |
| **设计建议** | 定义**sidecar 元数据模型**（xattr/ACL/资源分叉/稀疏性/DOS 属性序列化进 manifest）+ **跨端恢复降级矩阵**（目标平台不支持的项目明示跳过或存为可见 sidecar 文件），恢复报告逐项列明 |

### 3.4 移动端角色

- **iOS**：系统在后台约 **30 秒** 即杀进程；`BGAppRefreshTask` 30 秒/次、`BGProcessingTask` 数分钟但**完全由系统择机**（通常夜间+充电+Wi-Fi）。可行路径：PHPhotoLibrary 变更观察做增量 + background URLSession 续传 + 前台打开时冲刺上传。另：LAN 发现需要 **Local Network 隐私权限**，mDNS/组播需申请 [multicast entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.networking.multicast)（需 Apple 审核）。
- **Android**：相册走 MediaStore/Photo Picker；全文件访问需 MANAGE_EXTERNAL_STORAGE 或 SAF；后台靠 WorkManager + 电池优化白名单引导。Syncthing-Fork 的存活证明 Android 上「常驻备份代理」可行。
- **定位**：移动端=「相册/文件备份采集器 + 恢复查看器」，元数据管理、保留策略配置留在桌面端；iOS 不承诺实时性。

## 4. 传输技术

### 4.1 断点续传与弱网优化

- **内容寻址分块（CDC）+ 每块独立加密**是同时解决去重与续传的基座：块是重试/校验/恢复的最小单位，天然支持块级重试与并行（restic/Kopia/Duplicacy/Filen 均此路线）。
- **manifest 增量清单**：本地 SQLite（扫描缓存：路径→mtime/size/inode 快速跳过）+ 远端加密 manifest 对象（快照树）；断网/换网后仅重传缺失块。
- 弱网（移动网络）策略：小分块上限、并发数自适应（RTT/丢包探测）、指数退避+抖动、Wi-Fi-only/计量网络开关、后台会话（iOS background URLSession / Android WorkManager 约束）。
- 大文件走 S3 multipart（自适应段大小适配 10,000 段上限）；R2/B2 上 Class A/Class D 费用与块数线性相关 → 默认块均值不宜过小（R2 免费额度 1M Class A/月 ≈ 1TB/1MiB 块刚好打满）。

### 4.2 传输安全

- **TLS 1.3 + 应用层 E2E 双保险是行业标准**：restic/Kopia/Filen 全部在客户端加密后才出栈，传输层加密只是防御纵深的一层，S3/B2 的 TLS 不保护你免受云商读取。backguard 必须同构：**BYO 桶也一律客户端加密**。
- **证书固定（pinning）**：对备份工具弊大于利——桌面企业环境 MITM 代理（Zscaler 等）常见，硬 pin 会直接废掉企业用户；建议仅官方云的移动端做可选 pin（默认关闭，附逃生说明），桌面端不 pin，配合正常证书校验即可（参照 [OWASP MASTG](https://mas.owasp.org/) 的权衡建议）。

### 4.3 隐私网络：Tailscale/WireGuard 回家备份

- 2026 年已是 homelab 标配：Q1 2026 社区笔记记录「Tailscale 取代手搓 WireGuard」（自动密钥轮换、可读 ACL、exit node）；典型形态：**手机/笔记本 → tailnet → 家里 NAS（SMB/NFS/restic rest-server/Kopia server）**；Tailscale 免费档 3 用户/100 设备，DERP 中继兜底 + 大多数连接可打洞直连。
- backguard 策略：不做自己的 VPN，**把 tailnet 地址当普通 IP/主机名支持**（SMB/SFTP/rest 协议即可），文档给 Tailscale 组网食谱；这比自带 overlay 网络便宜且可信。

### 4.4 点对点恢复（无云中转）

**可行，且有多重先例**：Kopia repository server / restic rest-server 本质就是「从另一台设备（服务器）直接拉块」；Syncthing 证明跨 NAT 的 P2P 块交换（BEP 协议）可产品化。backguard 形态：新设备加入时从 **LAN 内已有设备**直接拉块（mDNS 发现 + 证书配对，全速内网），云仓库只补差异；跨网则借 Tailscale/中继。历史教训：CrashPlan 的 P2P 备份死于商业模式而非技术——P2P 只应作为**加速层**而非唯一存储层。

## 5. 云端成本与合规

- **生命周期分层**：个人/小团队数据量下 B2/R2 已便宜到「全热」最优（$7–15/TB/月）；冷层仅适合「第 3 份归档副本」。
- **Glacier 恢复成本陷阱**：① 180 天最短存储，提前删除按剩余天数补款；② 取回费 Standard ~$0.02/GB + 12–48 小时时延（灾备最痛的是「恢复了 48 小时还没拿到数据」）；③ IA/Glacier 类 **128KB 最小计费对象**——去重型仓库小对象多，冷层费用可能反超热层；④ 取回到 EC2 免流量费但到互联网按 $0.09/GB。R2 的 IA 层取回 $0.01/GB 无时延，是更平滑的降频访问层。
- **出口费是最大隐性成本**：S3 恢复 1TB ≈ $92、OSS ¥256–512、COS ¥512；B2（3×）、R2（0）、Wasabi（≈1× 公平使用）对备份-恢复模式友好。**给用户的成本模型必须把「恢复一次多少钱」放首屏**。
- **数据导出权/可迁移性**：① BYO cloud 天然无锁定（仓库就是用户自己桶里的对象，rclone 可整仓搬走）；② 官方云须提供标准导出（明文文件树打包 + 密钥托管说明），欧盟 GDPR 第 20 条数据可携带权是底线（[gdpr-info.eu/art-20](https://gdpr-info.eu/art-20-gdpr/)）；③ 开放仓库格式文档化是信任卖点（restic 的格式文档 vs Duplicacy 闭源格式的社区争议是正反教材）。

## 6. backguard 云与多端架构建议（含业界先例）

1. **存储抽象层：原生核心 + rclone sidecar 长尾**
   原生实现 S3 兼容（AWS/B2/R2/Wasabi/OSS/COS）+ SFTP + WebDAV；rclone 作为可选外部进程覆盖剩余 provider（70+），不静态链接其库。凭据一律入 OS 钥匙串（Keychain/DPAPI/libsecret），不走 rclone config。先例：Kopia 自带多后端、Cryptomator 走系统挂载。

2. **双轨云：BYO cloud 为主打 + 官方云为转化器**
   - **BYO cloud**：原生客户端加密（TLS+E2E 双层），对象格式公开文档化；成本计算器展示「每月持有 + 一次全量恢复」双价。先例：Arq Backup（BYO 云商业成功范本）、restic/Kopia（开源范本）。
   - **官方云**：分块 + 每文件随机密钥 + 元数据全加密 + 独立恢复密钥（学 Filen，避开 MEGA 密码单点）；后端 R2+B2 双写双活（主 B2 $6.95/TB、恢复走 R2 零出口），即把 §1.2 社区玩法产品化。定价锚点：2TB ≈ $9–12/月（对齐 Filen €8.99/MEGA €9.99）。

3. **多端仓库模型：一设备一命名空间 + 账户级去重 opt-in**
   默认设备隔离（学 restic --private-repos + Kopia per-user），跨设备去重做成显式开关并明示 content-ID 存在性泄漏；防勒索：append-only 模式（学 restic rest-server --append-only）+ S3/Wasabi 上的 Object Lock 可选加固（R2/B2 无锁，用版本化+告警替代）。

4. **P2P LAN 模式：多源块传输**
   同一 manifest，块可来自云、LAN peer、或 tailnet 对端；新设备恢复优先 LAN 拉取（学 Syncthing 的发现/配对/中继三层，CrashPlan 为反例教训）；兼容 Tailscale 地址，不自建 VPN。

5. **跨端语义：sidecar 元数据 + 恢复降级矩阵**
   xattr/ACL/资源分叉/NTFS ADS/稀疏性/DOS 属性序列化进 manifest；跨端恢复逐项报告降级（填补 restic/Kopia 的 ADS/ACL 盲区——目前无开源工具覆盖，是明确差异化点）；路径规范化层处理大小写/非法字符/盘符→挂载点映射。

6. **移动端：采集器定位**
   iOS = 相册+文件备份客户端（PHPhotoLibrary 增量 + BGProcessingTask + background URLSession，明示系统限制）；Android = 全功能（Syncthing-Fork 先例）；两端均为「加密客户端」，密钥与恢复树在桌面端管理。

7. **自建引导**：文档与检测器支持 Garage/SeaweedFS/Ceph，**移除 MinIO 推荐**（社区版已维护模式+归档）；AGPL 组件（minio-go、Garage）只以进程外方式交互。

## 6.5 存储层决策（2026-09-29 用户定案）：rclone 统一管理

用户明确：**存储层以 rclone 为统一入口，remote 由用户自行增删，后续会持续加入其他 remote**。据此 v0 配置模型从单一 `WEBDAV_REMOTE` 升级为 `BACKUP_TARGETS` 数组（`"remote:子路径"` 多目标，设备段自动追加；旧写法兼容）。这与 §1.3 的评估（rclone 统一抽象层 + MIT 许可 + 70+ 后端）与 §6.1「原生核心 + rclone sidecar」的 Phase 2 远期设计不矛盾——Phase 0/1 期间 rclone 就是正式存储层而非临时方案；自研引擎的原生后端（B2/R2/S3）改为「Phase 2 视性能瓶颈再评估」，优先级让位于语义层产品验证。

## 7. 凭据外部化：密码管理器 sidecar（BORG_PASSCOMMAND 配方）

两个引擎原生支持外部命令取口令，密码管理器集成零定制代码。以 [rbw](https://github.com/doy/rbw)（Rust 版非官方 Bitwarden CLI，agent 常驻免重复认证）为例，config.sh / config.ps1 配方：

```bash
# 条目名是占位符；凭据一律由密钥服务读取，不写入任何源码/配置明文
export BORG_PASSCOMMAND="rbw get backguard-仓库口令"        # borg（Linux/macOS）
export RESTIC_PASSWORD_COMMAND="rbw get backguard-仓库口令"  # restic（Windows 侧同理）
```

定位与红线：

- **可选 sidecar，不进核心依赖**（与 rclone 同哲学）：无 rbw 环境下一切照常（`command -v` 探测 + 非致命跳过）；
- **vault 不是第一恢复路径**：恢复码纸质抄写照旧强制（03 §2.3）；vault 只算第 2 份副本，防丢防模糊的冗余增强——灾难（账户锁定、主密码遗忘、agent 未登录）恰恰常发生在密码管理器不可用的时刻；
- **静默失效必须检测**：口令条目被删/agent 未解锁时备份会天天失败或挂起——preflight 检测（08 章 T2.2）验证 CLI 在位、agent 解锁、条目存在；drill（T3.4）的 `--from-bitwarden` 路径周期性真实验证 vault 恢复材料可用性；
- **爆炸半径明示**：备份口令入 vault 后，Bitwarden 主密码保护的资产变多——preflight 报告提示此取舍，由用户自行决定是否接受。
