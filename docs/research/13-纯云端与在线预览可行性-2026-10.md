# 13 · 纯云端备份与在线预览可行性 — 2026-10-04

> 起因：用户问「如果不让备份留在本地、只保留在云端，将来恢复时难道要下载全部备份吗？
> 是否可以在线预览 snapshot？」。本篇把答案钉在本项目的真实架构（borg/restic + rclone +
> 123Pan WebDAV + 语义层时间轴）与已登记的远端能力台账（05 §1.5）上，不写泛泛的通论。
> 性质：调研，不含实现。前置约束 = AGENTS §1 四条红线 + DEPLOY 的盲恢复设计不变。

## 1. 结论（两问各一句 + 一条架构判断）

1. **「要恢复就得下载全部」在当前 borg 架构下基本成立，在 restic 架构下不成立。**
   borg 的恢复必须先有（近乎）完整的本地 POSIX 仓才能 extract——从云端拉borg 副本 =
   `rclone copy` 整仓（当前 ~8.0 GiB）之后才能取一个文件；没有任何现成工具能对 WebDAV 上的
   borg 副本做「按需取 segment」的选择性恢复。restic 则是块去重 + 索引寻址：
   `restore --include` / `dump` 只下载目标文件的 chunk 所在的少量 pack，单文件恢复是
   秒-分钟级、KB-MB 级流量。
2. **在线预览可行，且不依赖「纯云端」**——但前提同样是 restic：`restic snapshots/ls`
   只取元数据（KB 级）；`restic mount` 把任意快照 FUSE 成只读文件系统在线浏览（macOS 需
   macFUSE）；`restic dump snap path > 文件` 是最轻的单文件取回，任何装了 restic+rclone
   的机器都能做（rescue.sh 的 restic 搜取路径正是这条工具链的雏形）。现成 GUI：
   restic-browser（浏览+单文件恢复，支持 rclone 后端）、Backrest（Web UI）。
   **语义层时间轴本身就是「在线预览」的已有答案**：STORY/MANIFEST/COVERAGE/restore.md
   已随时间轴上云，人类可读、零下载、天然合规（§1.1）——它缺的只是文件内容级的随机访问。
3. **架构判断**：「不留本地、只留云端」= 把事实源从本地仓换成云端仓。borg 路径走不通
   （见 §3），restic 路径走的是官方设计位：restic → `rclone serve restic`（REST 桥）→
   任意 rclone remote 含 WebDAV。但这条放大 123Pan 的全部已知毛病（§4），且把红线 §1.4、
   备份窗口、校验成本全部改写——**是 M4 之后按 dogfood 数据说话的架构提案，不是观察期动作**。

## 2. 为什么 restic 不用「下载全部」——恢复语义的引擎差

| | borg | restic |
|---|---|---|
| 仓格式 | 本地 POSIX 文件树（segments/ + index） | 对象 + 索引，后端抽象（local/sftp/rest/rclone/S3…） |
| 远端仓支持 | 仅 SSH（对端跑 borg）或本地/挂载文件系统 | **原生**：`rclone:remote:path` 即云上活仓 |
| 取一个文件 | 需要本地完整仓（index→segment 全在本地） | 索引（小）→ 定位 pack → 按 Range 取需要的块 |
| 在线列快照/列文件 | 需本地仓 | `snapshots` / `ls --json`，KB 级流量 |
| 在线浏览 | `borg mount`（需本地仓+macFUSE） | `restic mount`（直接挂云端仓，macFUSE） |
| 灾难重建 | 下载整仓副本（唯一路径） | 理论上也可全量（`restore` 全部），但按需恢复从不要求 |

本项目实测锚点：`borg-files` 本地仓 ~8.0 GiB（du 实测）；rescue.sh 已内建两种引擎的
自动判定与搜取，age 账本路径（干净机器 + 云端目录 + 纸质恢复码 + **密钥第二处离线副本**，
`recovery-identity.enc` 已定不上云）就是「本地全丢」场景的既定设计——**这个场景我们设计过，
但它的 borg 分支代价正是 §1.1 说的整仓下载**。

带宽量级（家庭宽带，下载按 300 Mbps ≈ 4 min/GiB）：整仓重建 ~8 GiB ≈ 半小时级，一次性、
可接受；**真正的痛点不是总量而是「每次恢复都要整仓」的 borg 语义**。单文件按需恢复
（restic）= 少数 pack 的 Range 读，取决于远端是否支持 HTTP Range——**123Pan 的 Range
支持未探测（05 §1.5 待补项）**，这是在线预览可行性的第一个实验缺口。

## 3. 「不留本地」在本项目里的真实代价

1. **Mac 侧必须换引擎**：本地 borg → 云端活仓只有 restic 一条路。等于把三平台的本地仓
   统一迁 restic（Windows 侧本来就是 restic，反而是顺的）；borg→restic 没有“仓迁移”，
   只能重灌（首次全量重传 ~8 GiB 上行，家庭上行 20-30 Mbps ≈ 1-2 小时）。
2. **123Pan 特性从「同步烦恼」升级为「备份路径故障面」**（05 §1.5 台账）：
   ~40MB 级文件偶发 500（restic pack 默认大小恰在此量级上下，需调 `--pack-size` 或重试策略）、
   大目录 DirMove 500、大小写不敏感、**上载吞吐=备份窗口**（夜间增量靠去重很小，但
   `check --read-data` 月度整仓读、`forget --prune` 直写删除都变成云端长事务）。
3. **红线与设计重写**：§1.4「云端只增不减」是对 push 模式说的；cloud-only 后 prune 直接
   在云端删 pack，这条红线要按「云端是事实源」重写；自证（A6）的「本地↔云端单向包含」
   语义反转成「云端即本体」；`rclone 只比大小` 的陷阱从「副本陈旧」升级为「活仓损坏不可见」
   ——check 从月度建议变成保命项。
4. **密钥面不变但更硬**：本机不再持有任何数据后，密钥第二处离线副本 + 纸质恢复码从
   「灾难预案」变成「唯一钥匙」，丢失=全部数据不可恢复（这比本地模式更锋利）。
5. **获得的**：零本地占用（8 GiB 级）；换机/多设备天然共享事实源；在线预览与按需恢复
   开箱即得；时间轴与引擎同源。

## 4. 折衷谱系（不必一步到纯云）

| 档 | 形态 | 代价 | 备注 |
|---|---|---|---|
| 现状 | 本地=事实源，云端=只增副本+自证 | 8 GiB 本地 | 已是「本地全丢可恢复」设计（rescue.sh 盲恢复） |
| 本地收窄 | restic 直写云端活仓；本地只留最近一份归档级缓存或不留 | 架构迁移 + §3 全部代价 | 「cloud-only」本体；建议 M4 后按 dogfood 数据提案 |
| 在线预览加层（不动架构） | 语义层时间轴已上云=目录/计数级预览；再补 webui 一页渲染 restore.md/COVERAGE | 半天级 | 零风险，A2 第二增量候选 |
| 文件级在线预览实验 | 云端放一个 restic 仓（如 Windows dogfood 侧），用 restic-browser/`restic ls` 实测 123Pan 的 Range 与时延 | 一次探测 | **05 §1.5 台账补 Range 一行的唯一途径** |

## 5. 建议（按观察期纪律排序）

1. **现在不动架构**（观察期，且 Mac 侧换引擎是 M4 级决定）。
2. **零风险实验（可排进 dogfood/T1.6）**：Windows 真机接入后天然产生云端 restic 仓，
   届时用 `restic -r rclone:Backguard:... snapshots/ls` 与 restic-browser 实测
   123Pan 的 Range 支持、单文件恢复时延、`restic mount` 可用性——把「在线预览」从
   推断变成台账事实。
3. **半天级小增量（A2 候选）**：webui 加「快照内容预览」页——渲染云端时间轴里每份快照的
   restore.md/COVERAGE（已上云、已合规），人不需要任何引擎就能「预览备份里有什么」；
   文件内容级取回仍回 rescue 工具链（§1.5 确认门不变）。
4. **真要纯云**：M4 后出架构提案（迁 restic + rclone REST backend + pack 大小与重试调参 +
   check/云端 prune 的节奏 + 密钥离线副本升格为唯一钥匙的规程），先 dogfood 一台再谈。

## 6. 直接回答用户的两句话

- **要下载全部吗？** 当前 borg 架构：云端恢复 = 先整仓副本下载（~8 GiB）才能取任何文件——
  你的担心成立；restic 架构：单文件恢复只取它自己的块，KB-MB 级、秒-分钟级，永不要求全量。
- **能在线预览吗？** restic 可以（`ls` 元数据、`mount` 文件系统级浏览、restic-browser/Backrest
  现成 GUI）；borg 不行（需要本地仓）；而**语义层时间轴已经是你随时间轴上云的「预览层」**，
  现在就能在云端看每个快照讲了什么——文件内容级的在线浏览是 restic 迁移后的红利，不是今天的缺口。
