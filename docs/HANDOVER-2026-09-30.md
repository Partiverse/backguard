## 1. 项目一页纸

**Partiverse Backup（仓库名 backguard）**：三平台（Linux/macOS/Windows）个人备份系统。
在成熟引擎（borg/restic）与 rclone 之上做两层增值：

1. **语义层**（「看得懂的备份」，全行业空白一）：每次备份自动生成裸文件管理器可读的
   `MANIFEST.txt`（明文摘要卡）、`STORY.md`（中文叙事 + 断档 >48h 置顶警示）、
   `restore.md`（本快照恢复指引）、`COVERAGE.txt`（「什么没被备份」明示 + 排除规则变更告知）；
   完整文件名单独密封进 age 加密的 `manifest.json.enc`。
2. **强制恢复码体系**（全行业空白二）：age 双 X25519 recipient（主身份 + 恢复码包裹的
   救援身份），`bg drill` 周期抽样真实取回文件验证恢复链路。

**当前阶段**：Phase 0 验证期（14 周计划 2026-10 → 2027-01）的**观察期起点**。
核心功能面已全部落地并在一台真实设备实战运行；代码迭代降速，重心是被动观察与 dogfood。
战略背景与全部调研依据在本地 `research/` 8 章 + `PRD.md`（见 §2）。

### 4.5 `RunAtLoad`：判断依据与执行结果（10-01 10:40 已落地）

- **它在真机上的实际代价已经出现过一次**：10-01 02:41 那次重载多跑了一发全量上传，凭空多出
  `0241-night` 快照，把「一天几个快照」的观察口径搅浑（§4.3）。模板去 RunAtLoad（7c1df6e）后，

  重载）都会再复制一次这种噪音。「等下次计划内改 plist 顺手对齐」的问题在于：那次重载本身就是
  RunAtLoad 会咬的场景，而「下次」没有日期。
- **今天改的窗口条件是现成的**：当下没有备份在跑（`pgrep -fl 'backup.sh|borg|restic|rclone'`
  实测为空），改完 `bootstrap` 也不会立刻跑（新 plist 无 RunAtLoad），下一发就是 10-02 02:34。
- **免费验收**：明早会话正好用 10-02 那发同时验两件事——`launchctl print gui/$UID/com.partiverse.backup`
  的 `runs` 计数 +1、`launchd.out.log` 里有 02:34 起的完整一轮、快照目录只比今天多 1（没有多余
  的第二个快照即证明 RunAtLoad 真去掉了）。等到夜里之后再做就丢掉这一发样本。
- **做法（不要手工编辑 plist）**：`cp -p` 备份现有 plist → 从部署树 `init.sh` 拿模板渲染一份、
  与真机那份比对 → `bootout` → 覆盖 → `bootstrap` → `launchctl print` 确认在位且本轮没跑。
  **两个当场踩实的坑**：
  ① 「跑 `INIT_SCHED_NO_REGISTER=1 ./init.sh` 来重渲染」是**错的**——这个变量只跳过 launchctl
  注册，向导末尾的「首次备份」照样无条件跑（`init.sh` 最后那段 `"$SCRIPT_DIR/backup.sh"`），
  等于白烧一发全量上传，正是 RunAtLoad 那个毛病的翻版。真做法是把 heredoc 单独截出来求值：
  `sed -n '/<<PLIST/,/^PLIST$/p'`（连 `cat > "$PLIST_DIR/…"` 那行一起取，先 grep 一下
  `^PLIST$` 确认行号没漂移），绑 `SCRIPT_DIR/LOG_DIR/LAUNCH_BASH/SCHED_H/SCHED_M`
  与一个临时 `PLIST_DIR` 再 source。
  ② **比对用按键比较，不要用文本 diff**：模板是紧凑单行，真机那份被 launchd 重排过缩进，
  `diff` 会显示「整份都不一样」而看不出真实差异只有一个键；`python3 -m plistlib` 逐 key 比
  才拿得到干净结论（`Label/ProgramArguments/Start*/Standard{Out,Error}Path` 五个 SAME，
  唯一 DIFF 就是 `RunAtLoad: live=True → new=<缺失>`）。
- **反面情形**：如果今明两天本来就打算动调度（比如要改 02:34 的时间点），那就不必单独跑这一趟，
  合并进那次即可——除此之外没有理由继续留着它。
- **执行记录（10-01 10:40）**：改前基线先取好（三仓库各 4 个归档、timeline 叶子 9 个、
  `launchctl print` 状态 `not running`、`pgrep -fl "backup.sh|borg|restic|rclone"` 为空）→

  避免「卸载失败还往里写」）→ `install -m 600` → `bootstrap` rc=0。验收：
  `active count = 0` / `state = not running` / `last exit code = (never exited)`、

## 7. 关键设计决策与实测教训（新会话必读，防重蹈）

**设计定案（用户亲自拍板，勿擅改）**：
- 命名体系：`<设备名>-<系统>` 全小写、不含 OS 版本（大小写不敏感网盘的安全交集 + 系统升级不分裂历史）；品牌原名进 `profile.json`；点转连字符。
- 存储层：rclone 统一管理，`BACKUP_TARGETS` 多目标（用户原话「后面还会有其他 remote 加入」）。
- 密码管理器：rbw（Bitwarden CLI）经引擎原生 PASSCOMMAND 做可选 sidecar，定位是纸质恢复码的第 2 份副本，**绝不替代**；`drill --from-bitwarden` 周期真实验证。
- 云端策略（未来）：B2 主存 + R2 零出口恢复双写（Phase 1）。

**实测教训（全部有提交记录可查）**：
- **时间口径**：borg 1.4.5 的 info start 是 naive 本地时间（不是 UTC——CI 的 TZ=UTC 曾造成盲测误判）；launchd 幻影 +8h 事故后 parent-time 改由归档名解析；Python 3.9 `fromisoformat` 拒绝 `+0800`，parse_iso 容错 ±HHMM/Z；demo/测试时间一律 naive。
- **launchd 受限 PATH**：`command -v age` 扑空 → `find_age` 补 /opt/homebrew、/usr/local；系统 python3 3.9 兼容必须保持。
- **bash 3.2/5 双轨** + `set -euo pipefail` 陷阱 + shellcheck 三连（SC2154/SC2318/SC2199）——细则见 AGENTS.md §2。
- **age 只读 /dev/tty**：`printf | age -p` 喂不进，expect 驱动（init-keys.exp）为正解。
- **123Pan WebDAV**：大小写不敏感、DirMove 500、大文件偶发 500——目录迁移用 copy+验证+purge；新 remote 先跑 `test_remote_caps.sh`。
- **隐私级 bug 案例**：单文件曾被两级细化误写成目录名 → 引入 known_dirs 目录证据机制；2026-09-30 又抓到残留回退（known_dirs 缺失时仍允许两级名，纯文件清单下 `Pictures/IMG_0001.jpg` 直接进 STORY）→ 删除回退，无证据一律退回一级，demo run 补目录证据保持与真实 run 同构；密封清单路径是 auto-strip 后形态、borg 归档内是原始路径 → `bg sample` entries 带 raw 字段。
- **rclone 空子路径**：`"remote:" + "/设备"` 被解析为文件系统绝对路径 → sync_target 归一化。
- **Mimosa（ZCode 安全审计插件）分层约束**：Python 侧一切变量子进程调用被强制拦截 → bg 只做纯文件系统检查，引擎/凭据/网络在 bash 编排层。Qoder 无此 hook，但该分层已成架构约束，遵守它。
